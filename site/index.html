SCAN ▸ YOUR CI · AMOLED HUD · RGB LED

Reads your CI's power level.

A retired Samsung Galaxy S3 Neo sits on the desk and shows the GitHub Actions status of your most active repos on its AMOLED screen, as a Scouter HUD. Its RGB notification LED becomes your build light. When something breaks, the lens cracks: POWER LEVEL DROPPING.

01 · HOW IT WORKS

One small server, one old phone.

The aggregator polls GitHub with ETags, so quiet repos cost nothing against the rate limit. It combines each commit's workflows into one status and streams a small JSON document to the phone over server-sent events. The phone draws it and drives the LED. That's the whole system.

02 · SCREENS

Swipe between three screens. Alerts take over.

  • Morning briefing. When the screen turns on, what broke, recovered and deployed overnight.
  • Wave to wake. At night, wave over the phone to see the dashboard for 20 seconds.
  • Deploys. With Coolify connected: each repo's latest deployment beside its CI, and a warning when it shipped a commit whose CI failed.
  • Project icons. Found in the repo or on the deployed site, shown dimmed beside the name.
  • History. A 14-day power sparkline under PWR.
  • Over the air. One command builds, publishes and installs a new version on the phone.

03 · STATUS LIGHT

Readable from across the room, screen off.

The notification LED only goes red for fresh trouble. With several long-red repos, "any failure" would keep it red forever, and a light that is always red means nothing.

04 · STAGES & WEATHER

Every project gets its own battlefield.

Behind the HUD sits a stage picked by the Focus project, with its sky tinted by the hour. The weather mirrors the LED: ki sparks while a build runs, a storm and a cracked ground on a fresh failure, static without a link. When the whole Grid turns green, the seven Dragon Balls appear for a minute. Every scene is an original drawing made in code, kept dim, and only redrawn when something changes.

05 · DESIGN

Rules for a screen that is on all day.

Black stays black.

Chrome is thin teal lines, deliberately bluer than the green that means "passing". An AMOLED pixel that is black is off.

Status is never decoration.

Status words stay large and in their colours. The HUD only frames them, and icons and scenes are dimmed so status stays the brightest thing on screen.

Animation only on change.

A new state sweeps a scan line over the lens and counts changed power levels for under a second. Otherwise nothing moves, except a ±4 px burn-in shift once a minute.

Off when you are.

The screen follows a schedule (Mon–Fri 09:00–19:00 by default) and only wakes at night for an alert or a wave.

06 · SET IT UP

An evening's work, if you have an old Android phone.

Any Android 9+ phone runs the app. The status LED needs a phone that still has a notification LED, and a ROM that honours notification light colours. Scouter is built against the S3 Neo on LineageOS 19.1.

  1. Run the aggregator

    Deploy aggregator/ anywhere that runs a container. On Coolify: build pack Dockerfile, base directory /aggregator, port 8080, a persistent volume on /data, and leave Coolify's health check off (the image is distroless).

    SCOUTER_TOKENrequired: the bearer token the phone sends
    SCOUTER_GITHUB_TOKENrequired: fine-grained PAT, read-only Actions, Contents, Pull requests, Metadata
    SCOUTER_ADMIN_PASSWORDoptional: enables the admin UI at /admin/ (12+ characters)
    SCOUTER_COOLIFY_URL · _TOKENoptional: deploy status, read-only token
    SCOUTER_HOOK_TOKENoptional: for Claude Code hooks
    SCOUTER_RELEASE_TOKENoptional: over-the-air releases
    # try it locally
cd aggregator && SCOUTER_TOKEN=dev SCOUTER_GITHUB_TOKEN=$(gh auth token) make run

  2. Install and configure the phone

    Configuration is only accepted over adb, so no other app on the phone can point it at a server of its own and collect the token.

    cd android && ./gradlew :app:assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
adb shell appops set dev.recica.scouter SYSTEM_ALERT_WINDOW allow
adb shell dpm set-active-admin dev.recica.scouter/.AdminReceiver
adb shell "am broadcast -n dev.recica.scouter/.ConfigReceiver \
  --es url https://scouter.example.com --es token SECRET \
  --es schedule '1-5 09:00-19:00'"
adb shell am start -n dev.recica.scouter/.DashboardActivity

  3. Lock it to the desk (optional)

    As device owner, Scouter can run as a kiosk: no Home, no Recents, no notification shade. It can also install its own updates silently.

    adb shell dpm set-device-owner dev.recica.scouter/.AdminReceiver

    Switch Kiosk on in the admin UI or the phone's settings (long-press the top strip). Release device ownership there before uninstalling.

  4. Ship updates over the air

    tools/release.sh        # bump, build, publish, wait for the phone
# version 0.3.8 (11) -> 0.3.9 (12)
# phone runs 0.3.9 (0.3.9 | installed)

  5. Hook up Claude Code (optional)

    Copy tools/claude-hook.sh to ~/.config/scouter/hook.sh and register it for UserPromptSubmit, Notification, Stop and SessionEnd. It forwards only the session id, the working directory and the event name, never prompts or transcripts.
